# Poem — Дизайн веб-клиента (`ui-client.md`)

Документ описывает интерфейс веб-клиента игры «Поэма»: экраны, компоненты, карты
«элемент UI → эндпоинт HTTP API», состояние, polling и обработку ошибок. Является
реализуемой спецификацией для фронтенда; требования «что показывать» заданы в
`design.md` §16, справочник эндпоинтов — в `guide_server.md` §6, пользовательский
цикл — в `guide_client.md`.

**Принципы дизайна (наследуются из свода правил Rev 3):**

1. **Клиент тонкий.** Никаких локальных копий законов, черновиков и ревизий: всё
   юридически значимое живёт на сервере. В `localStorage` — только сессионный токен,
   выбранный мир и UI-настройки (тема, язык). Закрытая вкладка ≠ потерянная правка.
2. **Игровое время первично.** Все длительности (переходные периоды, договоры, войны,
   интервалы ходов) отображаются в игровых годах/сезонах, никогда — в «числе ходов»
   или реальном времени. Реальные часы показываются только как вспомогательная
   подпись к `simulation_cutoff_at`.
3. **Никаких штрафов за время суток.** UI нигде не создаёт ощущения «дедлайна до
   вечера»: уведомления после подачи правки — дословно тексты сервера (§16.3),
   включая «Время подачи не влияет на эффективность».
4. **Один источник истины для статуса правки.** Бейдж «войдёт в текущий срез /
   перенесена в следующий ход» берётся только из ответов сервера
   (`will_apply_in`, buckets из `/laws/pending`, `/laws/{id}/status`), клиент ничего
   не вычисляет сам.
5. **Offline-tolerant.** Обрыв соединения не блокирует ввод: черновик можно печатать,
   отправка ставится в очередь повторных попыток с backoff; несохранённые символы
   подсвечиваются индикатором синхронизации.

## 2. Экраны

### 2.1. Дашборд (`#/dashboard`) — §16.1

Верхняя плашка обязана отображать ровно блок из design.md:

```
Ход: 47
Эпоха: Классическая
Прошло времени с прошлого хода: 25 лет
Текущий год: 1840
Следующий ход охватит примерно: 25 лет
```

Компоненты:

| Компонент | Источник данных |
|---|---|
| Плашка хода (5 строк выше) | `GET /worlds/{id}/chronology` → `current_turn`, `current_era` (→ русская метка через таблицу эпох), `current_year`, `current_season`, `next_turn_span.years`; уточнение «прошло с прошлого хода» — `years_elapsed` последнего отчёта `GET /worlds/{id}/turns/report` |
| Баннер смены интервала | если `next_turn_span.years` последнего отчёта ≠ текущего `chronology.next_turn_span.years` → «Внимание: благодаря развитию цивилизаций следующий ход охватит {новое} лет вместо {старого}» (§16.1) |
| Индикатор сезона | `current_season` (`spring/summer/autumn/winter/long_night` — сезон задаётся сеттингом мира) |
| Таймер среза | `simulation_cutoff_at` открытого хода (wall-clock, подпись «до обработки хода»), плюс строка «⏸ Ход обрабатывается…» во время `processing` |
| Экономика | `view.economy[]`: производство, прирост населения, исследования, население — карточки по цивилизациям |
| Сводка законов | `view.laws[]`: количество активных, конфликты, переходные периоды |
| Уведомления хода | `view.notices[]` — человекочитаемые тексты сервера (§16.3), выводятся как есть |

Обновление: поллинг `chronology` каждые 30 с; `turns/report` — по событию публикации
хода (см. §5 Polling).

### 2.2. Хроника (`#/chronicle`)

Лента событий интервала (chronicle, §19.1): события хода упорядочены по **игровому
году**. Источник — `view.events[]` последнего опубликованного отчёта; каждый элемент
карточки: `year`, `kind`, `title`, `detail`.

- Типы карточек событий: смена эпохи («Наступает … эпоха»), отмена/приостановка
  закона, истечение договора, прибытие посла, завершение переходного периода,
  культурные вехи длинных интервалов.
- Фильтры по `kind`; группировка по эпохам; клик по году — подсветка соответствующего
  отрезка шкалы времени (горизонтальная шкала с нелинейными делениями: древние ходы
  длинные, поздние — короткие; визуализирует Civilization-like сжатие времени).
- Рядом с лентой — миниатюры иллюстраций этого хода из `#/gallery` (когда задачи
  примут статус `done`).

### 2.3. Список законов (`#/laws`)

`GET /laws?civilization_id={civ}` → таблица/карточки: название, статус-бейдж
(`active` / `in_transition` / `suspended` / `repealed`), традиция (прогресс-бар
`tradition`), возраст `age_years`, счётчик ожидающих правок (из данных `#/pending`).
Сортировка по возрасту/статусу; поиск по названию. Кнопка **«Новый закон»** →
диалог создания черновика (см. 2.5).

### 2.4. Карточка закона (`#/laws/:id`) — §16.2

Единый источник — `GET /laws/{id}` (одна операция возвращает всё требуемое §16.2).
Секции:

| Секция | Поля ответа | Вид |
|---|---|---|
| Текущая версия | `law.raw_text`, `law.status`, `law.tradition`, `law.age_years` | Markdown-рендер текста закона; бейдж статуса; шкала традиции с подписью «Традиция ограничивает резкие противоречащие изменения (§17.6)» |
| Черновики | `drafts[]` (`raw_text`, `status`, `updated_at`) | Список с переходом в редактор; статус-бейджи Editing/ReadyForPreview/Validated/Invalid/Submitted |
| Ожидающие правки | `pending_edits[]` + `will_apply_in` | Timeline-бейджи: «войдёт в текущий ход» / «перенесена в следующий ход — штрафа нет» (§16.3) |
| История версий | `version_history[]` | Diff-вью двух последних ревизий, статусы Applied/Superseded/Rejected/Failed |
| Переходные периоды | `transitions[]` (`kind`, `remaining_years`, `payload`) | Прогресс-бар обратного отсчёта **в игровых годах** |
| Конфликты норм | `conflicts[]` (`law_b`, `title`, `description`) | Предупреждающие чипы со ссылкой на вторую карточку закона |
| Фольклорные эффекты | `folklore_effects[]` (`spread`, `mutation`, `conflict_factor`) | Мини-графики значений |
| Образы закона | `visual_tokens[]` | Миниатюры устойчивых визуальных идентичностей (TASK-067) |

Действия в шапке карточки: «Поправить», «Отменить», «Приостановить»,
«Возобновить», «Уточнить толкование» — открывают форму правки (2.6).

### 2.5. Черновики (`#/drafts`) и редактор текста закона

Рабочий процесс (§3.3, всё хранится на сервере):

```
Создать ──► POST /laws/drafts {civilization_id, raw_text, target_law_id?}
Править ──► PUT  /laws/drafts/{id}            (автосохранение, см. ниже)
Валидация► POST /laws/drafts/{id}/validate    (вердикт нейросетевого слоя)
Подать  ──► POST /laws/{law_id}/revisions/{rid}/submit {draft_id}
Удалить ──► DELETE /laws/drafts/{id}
```

Редактор:

- Двухпанельный: слева текст закона (сырой текст), справа — каноническая форма
  (`canonical_draft: {kind, scope, effect}`), заполняется автоматически вердиктом
  валидации и редактируется вручную (для опытных игроков, сворачиваемая панель).
- **Автосохранение debounce 1500 мс** → `PUT /laws/drafts/{id}`; индикатор
  «сохранено на сервере / сохранение… / нет связи». Конфликт записи (открыт с двух
  устройств) решается «последний победил» + предупреждение с `updated_at`.
- Кнопка **«Проверить логику»** → validate; панель вердикта: `ok`, `status`
  (Validated/Invalid), `errors[]`, `warnings[]`, `specificity` (шкала конкретности),
  предложенная каноническая форма `canonical`. При `Invalid` черновик остаётся
  редактируемым — это прямо проговаривается в UI.
- Подача невозможна, пока черновик не `Validated` (кнопка «Подать» disabled с
  подсказкой запустить валидацию).

### 2.6. Форма правки закона (модаль/страница)

1. Выбор действия (9 типов §3.2): AmendLaw / RepealLaw / SuspendLaw / ReinstateLaw /
   ClarifyLaw / CancelPendingChange (+ CreateDraft/UpdateDraft/SubmitDraft живут в
   редакторе черновиков).
2. Текст правки (`raw_text`) + опциональная новая каноническая форма
   (`canonical_change.new_canonical`), параметры: `transition` (SimDuration — поля
   годы/сезоны/дни), `suspend_years`, `urgent` (чекбокс «срочное принятие»).
3. **Предпросмотр стоимости** — кнопка → `POST /laws/{id}/cost_preview`
   `{action, new_canonical, transition_years, urgent, raw_text}`: показывает
   `estimated_cost` (административный ресурс), `contradictions` (число конфликтов)
   и сноску сервера «Стоимость не зависит от времени подачи правки». Значение
   предпросмотра = цена, которая будет списана на срезе (дрейфа нет — api.py,
   preview_cost).
4. Отправка → `POST /laws/{id}/revisions`. Ответ содержит `notice` — **текст
   печатается в UI дословно**:

   ```
   Правка сохранена на сервере.
   Она будет учтена при симуляции хода.
   Время подачи не влияет на эффективность.
   ```

   либо (правка после среза, `deferred_to_next_turn`):

   ```
   Правка сохранена.
   Она будет учтена в следующем ходе.
   Штрафа за время суток нет.
   ```

5. Подтверждение уже записанной ревизии — `POST .../revisions/{rid}/submit` (без
   тела); отзыв неподтверждённой — `POST .../revisions/{rid}/cancel`.

### 2.7. Ожидающие правки (`#/pending`) — §15.3

Пять обязательных корзин из `GET /laws/pending` (+ шестая — Failed, §3.4):

| Корзина ответа | Заголовок в UI | Бейдж |
|---|---|---|
| `will_apply_this_slice` | Войдут в текущий срез | синий |
| `included_in_current_snapshot` | Уже в снимке этого хода | бирюзовый |
| `awaiting_next_turn` | Перенесены в следующий ход | серый + подпись «штрафа за время суток нет» |
| `superseded` | Перезаписаны более поздней версией | оранжевый (§17.2 «последняя подтверждённая версия побеждает») |
| `rejected` | Отклонены | красный, тултип — причина |
| `failed` | Сбой применения при симуляции | красный |

Для каждой правки: закон, действие, `received_at`, превью текста. Быстрые действия:
открыть карточку закона, отменить (cancel). Аналитический вид снимка:
`GET /laws/snapshot` — какие id законов/правок читает симуляция прямо сейчас
(секция «Снимок хода» на этом же экране).

### 2.8. Дипломатия (`#/diplomacy`)

- Активные договоры и посольства: `view.diplomacy[]` (`treaty_id`/`travel_id`,
  `kind`, `remaining_years`) — обратный отсчёт **в игровых годах**; создание —
  `POST /treaties` (длительность указывается в игровых годах).
- Войны: `view.wars[]` (`active`, `fatigue_attacker`, `fatigue_defender`) — шкалы
  усталости; объявление — `POST /wars`.
- События отрасли — фильтры ленты хроники (TreatyExpired / TravelArrival).
### 2.9. Галерея хроники (`#/gallery`)

Конвейер: ход ставит задачи в очередь → локальные GPU-воркеры сервера рендерят →
клиент забирает результат с того же сервера. UI:

- Сетка задач текущего и прошлых ходов: `GET /worlds/{id}/images` → `tasks[]`
  (`payload.kind`: hero-иллюстрация хода / law_vignette; `prompt`; `status`).
- Статусы: `queued` — спиннер «ждёт рендера», `running` — «рисуется на видеокарте
  сервера» (+`claimed_by`), `done` — изображение, `failed` — ошибка (`error`).
- Загрузка готового файла: `GET /images/{task_id}/asset` → `{base64, media_type,
  sha256}` → `<img src="data:{media_type};base64,{base64}">`; проверка sha256
  опциональна (debug-панель). Картинки кешируются в памяти сессии (не в
  localStorage — правила не кешируем).
- Пока задача не `done`, в сетке — placeholder с prompt-описанием сюжета
  иллюстрации; без GPU-воркеров игра играбельна: лента показывает «иллюстрации в
  очереди» (pending-счётчик из ответа).

### 2.10. Админ-разделы (роль `admin`)

- **Очередь рендеринга** (`#/admin/queue`): `GET /worlds/{id}/images/metrics` —
  глубина по статусам, загрузка воркеров `by_worker`, возвраты осиротевших аренд,
  среднее время ожидания/рендера, доля успеха. Опрос не меняет состояние очереди —
  панель может обновля часто.
- **Настройка мира**: регистрация цивилизаций `POST /worlds/{id}/civilizations`
  (`id`, `name`, `progress`, опциональные экономические поля) — форма с пояснением,
  что эпоха и интервал хода пересчитываются сразу (§9); управление visual tokens
  (TASK-067): `POST/GET/PUT/DELETE /api/v1/worlds/{id}/tokens`, `GET
  /api/v1/tokens/{id}/condition`.
- **Цикл хода (тестовый стенд)**: кнопки `turns/open` / `turns/run` с формой
  `started_at`, `simulation_cutoff_at`, `seed`.

## 3. Компонентная структура

```
App
├─ AuthGate (сессия: токен, мир, цивилизация, роль)
├─ WorldProvider (хроника + последний отчёт; общий для всех экранов)
├─ Layout: TopBar · Sidebar · Content
├─ screens
│  ├─ DashboardScreen   TurnBanner · IntervalShiftAlert · CutoffTimer
│  │                    EconomyCards · LawSummary · NoticesList
│  ├─ ChronicleScreen   EraScale · EventFeed(kind=…) · IllustrationStrip
│  ├─ LawsScreen        LawTable · StatusBadge · TraditionBar
│  ├─ LawCardScreen     sections: VersionPane · DraftsList · PendingTimeline
│  │                    HistoryDiff · TransitionGauge · ConflictChips
│  │                    FolkloreStats · TokenGallery · ActionBar
│  ├─ DraftEditorScreen TextPane · CanonicalPane · ValidationPanel
│  │                    SaveIndicator
│  ├─ EditFormScreen    ActionPicker · DurationFields · UrgentToggle
│  │                    CostPreviewCard · NoticeToast
│  ├─ PendingScreen     BucketColumns(×6) · SnapshotInspector
│  ├─ DiplomacyScreen   TreatyList · WarFatigueBars
│  ├─ GalleryScreen     TaskGrid · ImageSlot(status) · AssetLoader
│  └─ AdminScreens      QueueMetrics · CivRegistrar · TokenManager · TurnLab
└─ shared: ApiClient · Poller · ErrorBoundary · ToastHost · ConfirmDialog
```

Состояние (Redux/Zustand или аналог):

| Slice | Содержимое | Живучесть |
|---|---|---|
| `session` | токен, world_id, civ_id, роль | localStorage |
| `chronology` | ответ `/worlds/{id}/chronology` | память, поллинг 30 с |
| `report` | последний опубликованный отчёт (`view`) | память, обновление по публикации |
| `laws`, `drafts`, `pending` | проекции list/detail/card | память + stale-while-revalidate |
| `editor` | незакоммиченный текст черновика | память (не критично: сервер — источник истины) |
| `images` | карта task_id → status/asset | память сессии |

Локального хранения игровых данных нет (принцип 1).

## 4. Карта «действие UI → эндпоинт»

| Действие | Запрос | Тело (ключевое) | Что показать из ответа |
|---|---|---|---|
| Вход в мир | `GET /worlds/{id}/chronology` | — | доступность, плашка хода |
| Регистрация цивилизации (админ) | `POST /worlds/{id}/civilizations` | `id,name,progress,…` | повторный `id` → 400 |
| Обновить дашборд | `GET /worlds/{id}/turns/report` | — | `report.view.*` |
| Список законов | `GET /laws?civilization_id=` | — | карточки |
| Карточка закона | `GET /laws/{id}` | — | все секции §16.2 |
| Создать черновик | `POST /laws/drafts` | `civilization_id, raw_text, target_law_id?` | `draft.id` |
| Автосохранение | `PUT /laws/drafts/{id}` | `raw_text`, `canonical_draft?` | `draft.updated_at` |
| Валидация | `POST /laws/drafts/{id}/validate` | — | `validation.{ok,status,errors,warnings,specificity,canonical}` |
| Подать черновик | `POST /laws/{law_id}/revisions/{rid}/submit` | `{"draft_id": …}` | notice; только Validated |
| Записать правку | `POST /laws/{id}/revisions` | `civilization_id, action, raw_text, canonical_change{…}` | `notice` дословно |
| Подтвердить правку | `POST /laws/{id}/revisions/{rid}/submit` | — | статус Pending |
| Отменить правку | `POST /laws/{id}/revisions/{rid}/cancel` | — | исчезновение из pending |
| Статус правок закона | `GET /laws/{id}/status` | — | корзины §16.3 |
| Ожидающие правки | `GET /laws/pending` | — | 6 корзин §15.3 |
| Снимок хода | `GET /laws/snapshot` | — | инспектор среза |
| Предпросмотр цены | `POST /laws/{id}/cost_preview` | `action,new_canonical,transition_years,urgent,raw_text` | `estimated_cost, contradictions, note` |
| История ревизий | `GET /laws/{id}/revisions` | — | diff-вью |
| Открыть/просимулировать ход (админ) | `POST /worlds/{id}/turns/open` / `run` | `started_at, simulation_cutoff_at, seed` | `applied/deferred/superseded_revisions`, `notices`, `image_tasks` |
| Договор / война | `POST /treaties` / `POST /wars` | стороны, длительность в игровых годах | `treaty_id`, `duration_years` |
| Очередь иллюстраций | `GET /worlds/{id}/images` | фильтр `status?` | `tasks[], pending` |
| Забрать картинку | `GET /images/{task_id}/asset` | — | `asset.base64` → `<img>` |
| Метрики рендера (админ) | `GET /worlds/{id}/images/metrics` | — | глубина, by_worker, avg times |
| Visual tokens (админ) | `POST/GET/PUT/DELETE /worlds/{id}/tokens`, `GET /tokens/{id}/condition` | реестр образов | conditioning подсказки |

Все пути — под `/api/v1`. Клиент использует только GET/POST/PUT/DELETE из таблицы;
worker-эндпоинты (`claim/heartbeat/complete`) клиенту недоступны — они для GPU-
воркеров.

## 5. Обновление состояния (polling)

WebSocket в стеке сервера не предусмотрен — клиент использует таймеры:

| Данные | Интервал | Условие остановки |
|---|---|---|
| `chronology` | 30 с | всегда (вкладка видима) |
| `turns/report` | 60 с + немедленный refetch при изменении `current_turn` из chronology-поллинга | — |
| `laws/pending`, `/laws/{id}/status` | 20 с, пока есть Pending-правки | очистились корзины |
| `worlds/{id}/images` | 10 с, пока есть queued/running | все done/failed |
| `images/metrics` (админ) | 15 с | экран админа открыт |

Правила: поллинг замораживается, когда вкладка не видима (`document.hidden`);
все запросы проходят через один `ApiClient` с dedup одинаковых in-flight запросов;
один цикл обновления на весь app (WorldProvider), экраны подписаны на store.

Моменты инвалидации после действий пользователя: submit/cancel revision →
refetch pending + law card; PUT draft → nothing (ответ сервера — истина для editor);
run turn → refetch report + chronology + gallery.

## 6. Обработка ошибок и нестандартных ситуаций

Формат ошибки сервера: `{"error": …, "status": …}` (+`detail`); ValueError → 400.

| Ситуация | UI-поведение |
|---|---|
| Сеть недоступна | баннер «нет связи»; редактор остаётся активным, отправки в очередь retry (backoff 2/4/8/30 с, максимум 5); юридически значимо ничего не теряется — всё, что уже отправлено, на сервере |
| `404 no route` / `unknown id` | тост «Объект не найден — возможно, удалён с другого устройства», soft-refresh списка |
| `400` на submit невалидированного черновика | тост с текстом причины сервера; фокус на кнопку «Проверить логику» |
| `400` повторный `id` цивилизации | инлайн-ошибка формы регистрации |
| `400` asset «not ready» | слот галереи остаётся placeholder, задача помечена running/queued (refetch очереди) |
| `revision Failed` (сбой применения) | корзина `failed` в `#/pending` + бейдж в истории карточки закона; текст причины от сервера |
| Параллельная правка с двух устройств | last-write-wins + предупреждение с `updated_at` последней записи (правило §17.2 на уровне ревизий обеспечивает сервер) |
| Мир без GPU-воркеров | играбельно; галерея показывает очередь и счётчик `pending`, без ошибок |

Любой toast с текстом статуса правки **не переформулирует** серверные уведомления —
строки §16.3 выводятся дословно, чтобы игрок всегда видел гарантию отсутствия
временны́х штрафов.

## 7. Визуальный язык

- **Стилия «манускрипт + терминал»**: тёплый пергаментный фон панелей текста законов
  (моноширинный serif для `raw_text`), холодный нейтральный UI для служебных блоков —
  визуально разделяет «слово человека» и «машину симуляции».
- Эпохи задают акцентный цвет шапки (заря → охра, классическая → пурпур,
  индустриальная → селена, планетарная → циан) — соответствует ERA_STYLE_TOKENS
  генератора иллюстраций, так что картинка хроники и интерфейс согласованы.
- Статусные бейджи: Active — зелёный, InTransition — янтарный с песочными часами,
  Suspended — серый, Repealed — зачёркнутый; Draft statuses — отдельная палитра
  (Editing/ReadyForPreview/Validated/Invalid).
- Числа игрового времени — формат «лет / сезонов» с десятичным остатком
  («12.5 лет», «осталось 3 сезона»); real-time — только в скобках.
- Доступность: контраст ≥ AA, все серверные notices доступны скринридерам как
  `aria-live=polite`, редактор поддерживает keyboard-only workflow.
- i18n: русский по умолчанию (тексты уведомлений приходят с сервера и не
  переводятся на клиенте), каркас интерфейса — словарь ключей.

## 8. Технологический стек и развёртывание

| Слой | Выбор | Обоснование |
|---|---|---|
| Framework | SPA: React 18 + TypeScript (альтернативно Preact — легче для слабых устройств) | ES2020/CSS Grid — минимальные требования браузера из `guide_client.md` §3.1 |
| Сборка | Vite, статический бандл ~150–250 kB gzip | клиент тонкий, тяжёлых зависимостей нет |
| Данные | TanStack Query (stale-time = интервалы §5) или self-made Poller+store | единая схема refetch/invalidate |
| Редактор кода | plain `<textarea>` + markdown-preview; опционально CodeMirror для канонической JSON-формы | не блокирует ввод офлайн |
| Раздача | статика тем же сервером: `GET /` рядом с `/api/v1` (guide_client §4.1) | тот же origin — без CORS; air-gap совместимо, внешние CDN не используются |
| Аутентификация | session-token (cookie/Bearer на усмотрение обвязки); role `player|admin` | права на админ-экраны фильтруются на сервере; UI лишь скрывает разделы |

Пример минимальной проверки доступа перед входом в app:

```bash
curl -s http://<сервер>:8000/api/v1/worlds/w1/chronology
# ожидаемый JSON: current_turn, current_year, current_season, current_era, next_turn_span
```
