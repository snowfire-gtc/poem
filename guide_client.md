# Poem — Руководство пользователя клиента (`guide_client.md`)

Клиент «Поэмы» — это интерфейс, через который игрок читает отчёты хода, редактирует законы своей цивилизации и следит за миром. Клиент **тонкий**: он ничего не хранит юридически значимо — все черновики, правки и версии законов живут на сервере (правило §20 design-документа). Поэтому один и тот же черновик можно открыть с любого устройства.

Серверная часть описана в `guide_server.md`, правила игры — в `rules.md`.

---

## 1. Варианты клиентского интерфейса

| Режим | Для кого | Как получать |
|---|---|---|
| Веб-клиент (дашборд, карточка закона, лента хроники) | обычный игрок | браузер, обращается к HTTP API сервера (`/api/v1/...`) |
| CLI / скрипты автоматизации | администраторы, тестировщики, боты | Python-пакет `poem-sim` или HTTP-запросы |
| Интеграция через библиотеку | разработчики своих интерфейсов | импортировать `poem.api.WorldServer.handle(method, path, body)` напрямую (JSON-словари → JSON-словарь) |

---

## 2. Требования к аппаратному обеспечению

### 2.1. Веб-клиент (браузер)

**Минимально:**

| Компонент | Требование |
|---|---|
| CPU | любой современный 2-ядерный (смартфон среднего класса тоже подходит) |
| RAM | 2 ГБ |
| Экран | от 1024×640 (дашборд и карточка закона адаптивны) |
| Сеть | стабильное соединение с сервером (API + загрузка иллюстраций хроники) |

**Рекомендуется:**

| Компонент | Требование |
|---|---|
| CPU | 4 ядра |
| RAM | 4–8 ГБ |
| Экран | 1920×1080 — удобнее читать ленту событий и историю версий закона |
| Сеть | широкополосный доступ: после каждого хода клиент загружает отчёт с картинками-иллюстрациями из очереди генерации |

### 2.2. CLI / библиотечный клиент (Python)

| Компонент | Требование |
|---|---|
| CPU/RAM | минимальные: 1 ядро, 512 МБ достаточно для обмена с API |
| Накопитель | ~200 МБ (Python + пакет без внешних зависимостей) |
| Сеть | только если клиент удалённый; при библиотечном режиме («всё локально») сеть не нужна |

## 3. Требования к программному обеспечению

### 3.1. Веб-клиент

| ПО | Версия |
|---|---|
| Браузер | актуальные Chromium 110+, Firefox 115+, Safari 16+, Edge 110+ (поддержка ES2020, CSS Grid) |
| JavaScript | включён (клиентское приложение рендерит проекции отчёта из §16 design-документа) |
| Cookies/localStorage | разрешены — только для сессии входа; игровые данные там не хранятся |

### 3.2. CLI / библиотечный клиент

| ПО | Версия | Назначение |
|---|---|---|
| Python | **>= 3.11** | пакет `poem-sim` (в `pyproject.toml` зафиксировано `requires-python >= 3.11`) |
| pip / venv | любой актуальный | установка |
| requests / httpx (опционально) | любой актуальный | только для режима «удалённый клиент» поверх HTTP API; у самого пакета зависимостей нет |

## 4. Порядок установки

### 4.1. Веб-клиент

Установка не требуется — достаточно адреса сервера, выданного администратором мира. Проверка доступа:

```bash
curl -s http://<сервер>:8000/api/v1/worlds/<world_id>/chronology
# ожидаемый JSON: current_turn, current_year, current_season, current_era, next_turn_span
```

Если используется статическая раздача фронтенда с того же сервера — откройте в браузере `http://<сервер>:8000/`.

### 4.2. CLI / библиотечный клиент

```bash
git clone <репозиторий проекта> poem
cd poem/poem_sim
python3.11 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -e .                   # зависимости runtime отсутствуют — установка мгновенна
```

Проверка установки:

```bash
python -c "from poem.api import WorldServer; print('client libs ok')"
```

Для автономного «локального мира» (без отдельного сервера) клиент может сам собрать `WorldServer` в своём процессе — см. п. 5.2.

## 5. Порядок запуска и основной рабочий цикл

### 5.1. Веб-клиент (обычный игрок)

1. Откройте адрес мира в браузере, войдите под своей учётной записью цивилизации.
2. **Дашборд** (§16.1) покажет текущее состояние мира:

   ```text
   Ход: 47
   Эпоха: Классическая
   Прошло времени с прошлого хода: 25 лет
   Текущий год: 1840
   Следующий ход охватит примерно: 25 лет
   ```

   Если интервал хода меняется из-за развития цивилизаций, появится предупреждение вида: «благодаря развитию цивилизаций следующий ход охватит 10 лет вместо 20».
3. Откройте раздел **«Законы»** и карточку нужного закона (§16.2): текущая версия, ваши черновики, ожидающие правки, история версий, переходный период и его остаток, уровень традиции, конфликты с другими нормами и фольклорные эффекты.
4. Редактируйте текст закона в любое время суток — это безопасно:

   > Время подачи не влияет на эффективность. Правка, отправленная утром, вечером или ночью, имеет одинаковый игровой статус, если попала в один симуляционный срез.

5. Нажмите «Сохранить» (черновик ляжет на сервер) и «Подтвердить правку» (создастся ревизия). Клиент получит уведомление (§16.3):

   ```text
   Правка сохранена на сервере.
   Она будет учтена при симуляции хода.
   Время подачи не влияет на эффективность.
   ```

   либо, если срез уже наступил:

   ```text
   Правка сохранена.
   Она будет учтена в следующем ходе.
   Штрафа за время суток нет.
   ```

6. Перед подтверждением используйте предпросмотр стоимости (`POST /laws/{id}/cost_preview`) — правки оплачиваются административным ресурсом цивилизации.
7. После публикации отчёта хода изучите ленту событий интервала, экономику, фольклор, дипломатию и иллюстрации хроники (генерируются асинхронно **на видеокартах сервера**, без сторонних сервисов; клиент опрашивает `GET /worlds/{id}/images`, пока статусы не станут `done`).

### 5.2. Библиотечный/CLI-клиент

Пример полного цикла «закон → правка → ход» (проверен, работает):

```python
from datetime import datetime, timezone
from poem.api import WorldServer
from poem.chronology import Civilization

server = WorldServer("w1")                      # локальный мир (или HTTP-обвязка к удалённому)
server.add_civilization(Civilization(id="c1", name="Ромашки", progress=0.25))

# 1. создать закон
r = server.handle("POST", "/api/v1/laws", {
    "civilization_id": "c1",
    "title": "Подушный налог",
    "raw_text": "Все платят 1 монету",
    "canonical": {"kind": "tax", "scope": {}, "effect": {"per_household": 1}},
})
law_id = r["law_id"]

# 2. отправить поправку
r = server.handle("POST", f"/api/v1/laws/{law_id}/revisions", {
    "civilization_id": "c1",
    "action": "AmendLaw",
    "raw_text": "Освободить поселения до 200 жителей",
    "canonical_change": {"new_canonical": {
        "kind": "tax", "scope": {"population_below": 200}, "effect": {"per_household": 0}}},
})
rev_id = r["revision"]["id"]
print(r["notice"])                              # «Правка сохранена на сервере…»

# 3. подтвердить правку
server.handle("POST", f"/api/v1/laws/{law_id}/revisions/{rev_id}/submit", {})

# 4. просимулировать ход (open+run одним вызовом)
now = datetime.now(timezone.utc)
report = server.handle("POST", "/api/v1/worlds/w1/turns/run", {
    "started_at": now.isoformat(),
    "simulation_cutoff_at": "2026-10-12T00:00:00+00:00",
    "seed": 7,
})
print(report["view"]["dashboard"])
```

### 5.3. Типичные HTTP-вызовы клиента (удалённый режим)

```bash
# настройка мира: зарегистрировать цивилизацию (эпоха и интервал хода
# пересчитываются сразу после POST, §9)
curl -s -X POST $API/api/v1/worlds/w1/civilizations \
  -H 'Content-Type: application/json' \
  -d '{"id": "c1", "name": "Ромашки", "progress": 0.25}'

# хроника мира
curl -s $API/api/v1/worlds/w1/chronology

# мои законы
curl -s "$API/api/v1/laws?civilization_id=c1"

# карточка закона (всё для §16.2 одной операцией)
curl -s $API/api/v1/laws/$LAW_ID

# что попадёт в следующий срез
curl -s $API/api/v1/laws/pending

# последний опубликованный отчёт хода
curl -s $API/api/v1/worlds/w1/turns/report
```

## 6. Что делать при нестандартных ситуациях

| Ситуация | Действие клиента |
|---|---|
| Ошибка валидации текста закона (HTTP 400) | показать `error`; черновик остаётся на сервере в статусе `Invalid`, его можно править дальше |
| Правка отклонена сервером (`Rejected`) | она сохранена в истории версий для аудита, но ни в один ход не попадёт; создать новую ревизию |
| Не успели до `simulation_cutoff` | ничего делать не нужно — правка автоматически уйдёт в следующий ход, штрафа нет |
| Несколько правок одного закона за ход | применится **последняя подтверждённая**; предыдущие будут помечены `Superseded` (видимо в `GET /laws/pending`) |
| Картинки хроники ещё не готовы | продолжать поллинг `GET /worlds/{id}/images`; отчёт доступен и без иллюстраций |
| Оборвалась связь | все несохраненные изменения теряются локально — переспросите сервер (`GET /laws/drafts`), авторитетна только серверная копия |

---

## 7. Обновление клиента

- веб-клиент обновляется вместе с сервером (кэш браузера сбрасывается автоматически);
- CLI/библиотечный клиент: `git pull && pip install -e .` внутри активированного venv; совместимость протокола `/api/v1` сохраняется в пределах мажорной версии пакета `poem-sim`.
