# Poem — civ-like игра с нейросетевым слоем

**Poem** (пакет `poem-sim`, v0.4.0) — стратегия в духе Civilization, в которой игрок управляет
цивилизацией не прямыми командами, а **текстами законов**. Законы формулируются словами
человека, а нейросети на стороне сервера проверяют их логическую непротиворечивость и
генерируют иллюстрации к хронике мира. Все вычисления, включая генерацию изображений,
выполняются **на собственных видеокартах сервера — без использования сторонних сервисов**.

## Идея игры

Каждый игрок ведёт свою цивилизацию через эпохи: от Зари до Планетарной стадии. Вместо
кнопок «построить», «исследовать» и «объявить войну» игрок пишет и правит **законы** —
юридические тексты, которые сервер-симуляция интерпретирует и применяет к экономике,
населению, исследованиям, дипломатии и войне. Нейросетевой слой оценивает смысл текста:
непротиворечив ли закон, не конфликтует ли с действующими нормами и обычаями, достаточно
ли он конкретен, чтобы порождать эффект.

Ход симуляции наступает не по фиксированному таймеру, а по **хронике мира**: интервал
между ходами сокращается с развитием цивилизаций (Civilization-like) — в древности ход
может длиться 60 игровых лет, а на планетарной стадии — четверть года.

## Ключевые особенности

1. **Законы как интерфейс управления.** Девять типов действий над правовым полем:
   предложение закона, поправка, отзыв, уточнение толкования и др. (см. `rules.md`).
2. **Все правки хранятся на сервере.** Клиент «тонкий»: локальных копий законов нет,
   состояние черновиков и ревизий — единственный источник истины (`design.md` §3).
3. **Логический срез хода (simulation_cutoff).** Правки, подтверждённые до среза, попадают
   в текущий ход; сделанные после — автоматически переносятся в следующий **без штрафа**.
   Время суток на игру не влияет (§2, TASK-060).
4. **«Последняя подтверждённая версия побеждает».** При конфликте редакций применяется
   самая свежая подтверждённая ревизия закона (§17.2).
5. **Динамический интервал ходов** по эпохам и скорости игры (quick / standard / epic /
   marathon); конфигурируется через `config/chronology.toml` (§6–§10).
6. **Стоимость правок зависит только от игровых факторов** — прогресса цивилизации,
   типа действия, конфликтов норм; никаких мета-штрафов за реальное время (§5).
7. **Нейросетевая валидация текстов** и **генерация иллюстраций хроники** выполняются
   локально, на видеокартах сервера, без обращений к внешним API и облачным сервисам.
8. **Отсутствие runtime-зависимостей у ядра**: пакет `poem` — чистый Python ≥ 3.11
   (`dependencies = []`), HTTP-обвязка и база данных подключаются снаружи.

## Архитектура

```
┌─────────────┐   HTTP/JSON    ┌──────────────────────────────┐
│ Веб-клиент  │ ◄────────────► │  HTTP-обвязка (FastAPI/Flask)│
│ CLI / SDK   │                │  poem/api.py — WorldServer   │
└─────────────┘                │  ~30 эндпоинтов /api/v1      │
                               └──────────┬───────────────────┘
                                          │ вызовы ядра (библиотечные)
                               ┌──────────▼───────────────────┐
                               │  Ядро симуляции poem         │
                               │  core · laws · pricing       │
                               │  chronology · turn · views   │
                               └──────────┬───────────────────┘
                    PostgreSQL (prod)     │     очередь image_tasks
               schema.sql — единая        │     claim/heartbeat/complete
               схема состояний            │
                          ┌───────────────▼───────────────┐
                          │ Локальные GPU-воркеры         │
                          │ PyTorch + diffusers, веса     │
                          │ моделей на диске сервера      │
                          │ (SDXL / Flux, air-gap OK)     │
                          └───────────────────────────────┘
```

Принципы:

- **Ядро детерминировано и не имеет внешних зависимостей** — его можно встроить в любой
  веб-фреймворк или использовать как библиотеку (проверенный пример — в `guide_server.md`).
- **Сервер — единственный владелец состояния**: законы, черновики, ревизии, хроника,
  задачи генерации, ассеты изображений.
- **Асинхронная генерация**: ход не ждёт рендера; иллюстрации копятся в очереди, воркеры
  забирают задачи по протоколу аренды (lease + heartbeat), готовые PNG хранятся и
  раздаются с собственного диска сервера.

## HTTP API

Все эндпоинты — под префиксом `/api/v1` (полный справочник — `guide_server.md`):

| Группа | Примеры |
|---|---|
| Мир | `POST /worlds`, `POST /worlds/{id}/civilizations` (настройка мира чисто по HTTP), `GET /worlds/{id}` |
| Хроника | `GET /worlds/{id}/chronology` (живой расчёт эпохи и следующего интервала), `POST /worlds/{id}/turns` → `run_turn` |
| Законы | карточка закона, черновики (`drafts`), правки (`revisions`), подтверждение/отклонение, ожидающие правки |
| Изображения | `GET /worlds/{id}/images` (очередь), `POST /images/{id}/claim` (lease), `POST /images/{id}/heartbeat`, `POST /images/{id}/complete` (asset_base64 → диск сервера), `GET /images/{id}/asset` (раздача PNG) |

Ответы — JSON; ошибки структурированные (`status`, `error`, `detail`); пути нормализуются
по идентификаторам токенов.

## Хроника мира и динамические ходы

Эпохи и базовые интервалы (`config/chronology.toml`, §7–§8 design.md):

| Эпоха | Интервал хода (standard) |
|---|---|
| Заря | 60 лет |
| Античность | 20 лет |
| Феодальная | 10 лет |
| Индустриальная | 5 лет |
| Информационная | 1 год |
| Планетарная | 0.25 года |

Текущая эпоха определяется по настроенному `era_source` (§9): по самой развитой
цивилизации, по медиане активных цивилизаций или по средневзвешенному прогрессу.
Скорость игры масштабирует интервалы (quick ×0.5 … marathon ×2). Все длительные
эффекты — договоры, войны, переходные периоды законов — измеряются в **игровом**
времени и корректно переживают смену интервала.

## Законы, черновики и ревизии

- Черновик создаётся на сервере, редактируется итеративно, затем превращается в ревизию.
- Ревизия проходит нейросетевую валидацию (статусы Pending / Validated / Invalid /
  Rejected) и подтверждается игроком; подтверждённая ревизия попадает в ближайший срез.
- Правки после среза хода не теряются и не штрафуются — они применяются со следующего хода.
- Конфликтующие нормы разрешаются по приоритетам типов законов и давности; обычаи и
  традиция закона (§17.6) ограничивают резко противоречащие изменения.
- Формула стоимости: базовая цена типа действия × модификаторы прогресса и конфликтов —
  никаких зависимостей от реального времени суток.

## Генерация изображений на GPU сервера

Полный конвейер автономен (`guide_server.md` §4.5, шаг 5 боевого запуска):

1. Ход ставит задачи иллюстраций хроники в очередь `image_tasks` (PostgreSQL / in-memory).
2. Локальный воркер (PyTorch + diffusers, SDXL/Flux на NVIDIA CUDA или AMD ROCm)
   забирает задачу: `POST /images/{id}/claim {worker_id, lease_seconds}`.
3. Долгий рендер продлевает аренду через `heartbeat`; упавший воркер не блокирует задачу —
   просроченная аренда автоматически возвращает её в `queued`.
4. Результат передаётся инлайном (`complete` + `asset_base64`) или по общему тому;
   сервер пишет PNG в песочницу `asset_dir` (защита от path traversal, лимит 32 МБ,
   sha256-метаданные).
5. Клиент забирает картинку с того же сервера: `GET /images/{id}/asset`.

Внешние API (OpenAI, Stability, CDN и т.п.) не используются; при отсутствии GPU-воркеров
игра продолжает работать, иллюстрации накапливаются в очереди. Интернет нужен лишь
однократно — скачать веса моделей.

## Быстрый старт

Требуется **Python ≥ 3.11** (из-за `tomllib`).

```bash
git clone <repo-url> && cd poem_sim
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[test]"

# библиотека без БД и HTTP — сразу играбельный сервер состояний:
python - <<'EOF'
from poem.api import WorldServer
w = WorldServer(world_id="w1")
print(w.handle("POST", "/api/v1/worlds/w1/civilizations",
               {"id": "rome", "name": "Рим", "progress": 0.3}))
EOF

pytest -q          # 106 passed
```

Для продактив-развёртывания: PostgreSQL 14+ (`schema.sql`), HTTP-обвязка поверх
`WorldServer.handle`, планировщик срезов хода и GPU-воркеры — пошагово в
[`guide_server.md`](guide_server.md).

## Требования

**Сервер (минимально):** 2 ядра CPU, 4 ГБ RAM (8 ГБ с воркером генерации), 10 ГБ диска,
Python ≥ 3.11, PostgreSQL 14+ (для prod). GPU опционален: без него игра работает, но
иллюстрации не рендерятся. Рекомендуемо для полной сборки: 4–8 ядер, 16 ГБ RAM, NVMe SSD,
NVIDIA GPU 12+ ГБ VRAM (CUDA 12.x) под SDXL; стек инференса ставится отдельным venv.

**Клиент:** современный браузер (Chromium / Firefox / Safari / Edge) либо Python ≥ 3.11
для CLI/SDK-клиента. Никакого локального состояния игра не хранит.

Подробные таблицы требований — в [`guide_server.md`](guide_server.md) и
[`guide_client.md`](guide_client.md).

## Тесты

106 автотестов в 12 файлах (`poem_sim/tests/`), покрывают ключевые требования Rev 3:

- `test_cutoff_and_time_of_day` — время суток не влияет; срез хода; перенос поздних правок;
- `test_server_laws_and_api` — серверные черновики/ревизии, настройка мира по HTTP;
- `test_chronology_intervals`, `test_interval_events` — динамические интервалы и события;
- `test_conflict_detection`, `test_prejudices`, `test_diplomacy_wars` — конфликты норм,
  предрассудки, договоры/войны в игровом времени;
- `test_stubs_closed` — все заглушки закрыты, lease-протокол и локальное хранилище ассетов;
- `test_views_and_images`, `test_law_card_api`, `test_failed_revision_status` — view-модели
  и статусы.

Запуск: `cd poem_sim && python -m pytest -q`.
